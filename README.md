# Химия · домашняя практика

Мобильный HTML-тест в стиле Cherry & Ice Blue: 24 реальных задания ФИПИ, черновик на устройстве и сервере, одна окончательная отправка, отдельный кабинет преподавателя. Ученица видит только подтверждение отправки. Баллы, эталоны, ошибки и аналитика доступны только преподавателю.

**Ограничение содержания:** подтверждены четыре разных задания №21. Остальная подборка — повторение №1–5, №8 и два задания №6 на ионный обмен. Поэтому это смешанный тест с отдельным блоком гидролиза, а не преимущественно тест №21. Источники, соответствие номеров и контрольные суммы находятся в `SOURCES.md`. Авторских заданий нет. Год, источник и ссылки ученице не показываются.

## Что понадобится

- Node.js 22 или новее для локальной сборки.
- Аккаунт Netlify и база PostgreSQL в Neon. Результаты хранятся в Neon, серверная проверка выполняется в Netlify Functions.
- Закрытый Git-репозиторий с содержимым этой папки. Папки `node_modules` и `.env` загружать не нужно. Ученице передают только ссылку на сайт и код доступа, не архив проекта: в серверных файлах есть ключи заданий.

## Развёртывание на Netlify

1. Создайте проект и базу в [Neon](https://console.neon.tech). В SQL Editor выбранной базы выполните **весь `schema.sql`** один раз. Этот шаг создаёт таблицы приглашений, черновиков, результатов и ограничений входа. Скопируйте connection string из Connect; используйте строку PostgreSQL с `sslmode=require`.
2. В Netlify выберите **Add new project → Import an existing project**, подключите репозиторий. Если файлы находятся в подпапке, укажите её как Base directory. Настройки из `netlify.toml`: команда `npm run build`, Publish directory `public`, Functions directory `netlify/functions`. Node — 22. Файл `pnpm-lock.yaml` и поле `packageManager` фиксируют зависимости.
3. В настройках проекта Netlify → Environment variables добавьте три переменные из таблицы ниже. Значения должны быть доступны **Functions**, для production; при использовании Deploy Preview задайте отдельную тестовую базу и отдельные секреты. Не добавляйте префиксы `PUBLIC_`, `VITE_` или `NEXT_PUBLIC_`.
4. Запустите развёртывание или повторный Deploy после добавления переменных. В журнале сборки должно быть сообщение о 24 заданиях, в разделе Functions — функция `api`.
5. Откройте `https://ВАШ-САЙТ.netlify.app/teacher.html`. Введите `TEACHER_SECRET`. Создайте код доступа с удобным обозначением попытки. Скопируйте полученную ссылку и сохраните её: исходный код показывается только при создании, в базе хранится его SHA-256.
6. Передайте ссылку ученице. На странице код уже подставлен; она нажимает «Открыть задания». Один код соответствует одной серверной попытке. Повторный вход с этим кодом продолжает черновик, после отправки показывает подтверждение. Для новой домашней работы создайте новый код.

**Обычное перетаскивание папки `public` в Netlify Drop недостаточно:** без серверных функций и базы не будет сохранения и защищённой проверки. Не выставляйте весь корень проекта как Publish directory.

| Переменная | Значение |
|---|---|
| `DATABASE_URL` | Строка подключения Neon PostgreSQL, включая пароль и `sslmode=require` |
| `TEACHER_SECRET` | Отдельный случайный секрет преподавателя, минимум 32 символа |
| `SESSION_SECRET` | Другой случайный секрет подписи сессий, минимум 32 символа |

Сгенерировать случайный секрет на своём компьютере можно командой ниже. Выполните её два раза и используйте разные результаты. Значения примеров в `.env.example` замените полностью. Секрет преподавателя сохраните в менеджере паролей; ученице его не передают.

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"
```

У Netlify Functions нет доступа к локальному `.env` после публикации: переменные нужно задать в настройках Netlify. Справка: [Netlify Functions](https://docs.netlify.com/build/functions/get-started/), [переменные функций](https://docs.netlify.com/build/functions/environment-variables/), [драйвер Neon](https://neon.com/docs/serverless/serverless-driver).

## Как работать с тестом

Ответы вводятся цифрами подряд. Навигация позволяет вернуться к любому заданию, голубой цвет отмечает заполненные поля. Условие можно увеличить. Правильность до отправки не раскрывается. Перед отправкой показаны число пропусков и поля с неожиданной длиной; при желании можно отправить неполную работу. Неправильные и пустые ответы дают 0 баллов.

Черновик сохраняется на устройстве сразу и на сервере через 700 мс после ввода. Статус под ответом различает эти случаи. При обрыве сети ответы остаются на устройстве; после восстановления можно продолжить. Чтобы перейти на другое устройство, дождитесь надписи о сохранении **на сервере**, затем используйте тот же код. Если локальное хранилище отключено, работает серверное сохранение при наличии сети. Одновременное редактирование на двух устройствах не поддерживается: последний сохранённый черновик заменяет предыдущий.

Сервер подтверждает отправку только после успешной записи в базу. При потере ответа на запрос можно нажать повторно: ранее сохранённая работа не меняется. Повторный вход после отправки также покажет подтверждение.

В кабинете преподавателя есть общий срез по темам, отдельные попытки, первичные баллы, ответ ученицы и эталон, раскрывающиеся условия и официальные источники. Список обновляется кнопкой. Показаны последние 200 работ; если их больше, появляется уведомление. Архив полностью сохраняется в PostgreSQL. Автоматического перевода в шкалу ЕГЭ нет. Максимум — 29 первичных баллов.

## Локальная проверка

```sh
corepack enable
pnpm install --frozen-lockfile
pnpm run build
pnpm test
```

Для полноценного локального запуска скопируйте `.env.example` в `.env`, задайте реальные тестовые значения, выполните `schema.sql` в отдельной тестовой базе и запустите `npx netlify-cli dev`. Пользуйтесь адресом, который напечатает Netlify Dev. Для сборки без доступа к базе достаточно `pnpm run build`; не открывайте HTML двойным щелчком, модульная загрузка и API требуют веб-сервера.

## Устройство защиты

- Клиентский `questions.json` содержит только идентификатор, тему, линию, путь изображения и длину ответа. Эталонов, баллов и источников в нём нет. Условия доступны публично, результаты защищены.
- Правильные ответы находятся в `server/questions.json`, включаются в серверную функцию и никогда не копируются в `public`. API кабинета возвращает их только после авторизации преподавателя.
- Сессии подписаны HMAC-SHA256, роли ученицы и преподавателя разделены; cookie имеют HttpOnly, Secure, SameSite=Strict. Сессия преподавателя действует 8 часов; ученицы — 30 дней. Секрет не сохраняется в localStorage.
- POST-запросы требуют совпадения Origin и JSON. Вход ограничен 20 запросами за 15 минут на роль и хеш IP. Исходный IP в таблице ограничений не сохраняется.
- `submissions.attempt_id` — первичный ключ. Отправка использует атомарный `INSERT ... ON CONFLICT DO NOTHING`. Даже параллельные запросы оставляют одну неизменяемую запись.
- Клиент не задаёт баллы, эталоны или идентификатор чужой попытки. Проверка ответов и расчёт аналитики происходят на сервере. Поля ученицы и подписи выводятся как текст, без вставки HTML.

Код доступа — пропуск к попытке. Его получатель может продолжить или отправить эту попытку; это не идентификация личности. Ограничение «одна отправка» действует на выданный код, а не на человека. Не публикуйте коды в открытом доступе.

## Обслуживание

Для резервной копии используйте экспорт базы Neon. Записи доступны владельцу базы и владельцу Netlify-проекта; это административный доступ помимо кабинета. Данные не отправляются почтой и не записываются в Netlify Forms. Хранится обозначение попытки, ответы, время и результат; имена вводить необязательно. Согласуйте срок хранения учебных работ.

Обновление оформления не удаляет данные. Содержимое и порядок заданий во время активных попыток не меняйте: версия теста фиксируется в отправленных результатах. Для другого набора создайте отдельный проект/базу либо заранее завершите действующие попытки. Не переносите этот код на хостинг только статических страниц.

Для выхода используйте «Выйти». При компрометации секрета преподавателя замените его и `SESSION_SECRET` в Netlify и выполните повторный Deploy — это завершит все действующие сессии. Данные в базе сохранятся. Не вставляйте реальные секреты в чат, Git или публичные файлы.

Затем создайте новый код для реальной работы.
